# 即刻一键分发

在即刻网页版（web.okjike.com）每条动态的操作栏加一个「分发」按钮，一键把帖子发到 **X、微博、豆瓣、Threads**。架构继承自「X 一键分发」插件（x-distributor）：不调平台 API，打开各平台官方发布页后注入脚本自动填内容，你确认后手动点发布（或开启自动点击）。

## 安装

1. 克隆或下载本仓库
2. 打开 Chrome，地址栏输入 `chrome://extensions`
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」，选择本仓库目录
5. 确保你已在同一 Chrome 里登录：**web.okjike.com、x.com、weibo.com、www.douban.com**

## 使用

1. 打开 https://web.okjike.com 的动态/个人主页，每条帖子操作栏最左侧会出现「分发」（黄色纸飞机图标）
2. 点击后弹出发布确认窗：可改正文、勾选平台（X/微博/豆瓣/Threads）、附原帖链接、带话题标签
3. 点「开始分发」→ 扩展打开各平台发布页（自动归入一个黄色标签组），自动上传原画质图片、填正文
4. 默认需要你到各标签页**手动点发布**；勾选「自动点击发布」可全自动
5. 发布完成后回到小窗点「关闭全部发布页」

### 找不到「分发」按钮时

按钮理论上不会消失：页面回前台、DOM 变化时都会立即重新注入。若仍找不到（如扩展刚重载、页面结构改版），**点浏览器工具栏的本扩展图标**，立即强制恢复所有按钮（图标上会闪一个 ✓）。在非即刻页面点图标会直接打开即刻首页。

## 平台细节

| 平台 | 入口 | 图片上限 | 正文限制 |
|------|------|---------|---------|
| X | x.com/compose/post | 4 张 | 280 units（中文约 140 字，超长可自动截断） |
| 微博 | weibo.com 首页发布框 | 9 张 | 超 140 字自动折叠为「展开」，可直接发 |
| 豆瓣 | douban.com 首页「我说」广播框 | 9 张 | 基本无限制 |
| Threads | threads.com intent/post 直链（正文预填） | 10 张 | 500 字（可自动截断） |

- 即刻图片自动取**原画质**（七牛 imageMogr2 2400 档，实测比列表缩略图大一个量级）
- 长帖在列表页被折叠时会先自动展开再提取全文
- 即刻视频帖：暂以文字形式分发（网页版视频是流式播放，直链抓取不稳定）

## 验证状态（2026-09-23）

- ✅ 即刻端全链路实测：按钮注入、正文/图片/话题/作者/原帖链接提取

## 目录结构

```
manifest.json            MV3 配置
content/okjike.js        即刻页注入：按钮 + 帖子提取（选择器 2026-09-22 实测）
background/service.js    消息路由 + 平台表 + 3 个自包含 adapter（executeScript 注入用）
tabs/publish.html/js/css 发布确认窗（原生 JS，无构建链）
icons/                   图标
```

## 说明

- 本扩展为个人开发的非官方工具，与即刻 / X / 微博 / 豆瓣 / Threads 均无关联
- 不调用任何平台 API，也不收集任何数据；发布动作发生在各平台官方页面里
- 平台页面结构改版可能导致选择器失效，届时欢迎提 issue

## 更新日志

- **2026-10-22** v0.2.0 新增分发渠道 **Threads**：走 threads.com 官方 `intent/post` 直链，发布弹窗直接预填正文（`injectUrl` 升级为按稿件动态生成），adapter 负责图片（最多 10 张，附件 input 不在时先点「图片」图标唤出）与点发布；正文未预填上时以 paste 兜底补填。正文限制 500 字，「超长自动截断」选项现同时作用于 X 与 Threads。
- **2026-10-21** v0.1.6 修豆瓣 v0.1.4 后仍报「未找到发布按钮」：根因是发博工具栏（含发布按钮）要吃到真实输入事件才渲染，旧的 `value` 赋值＋合成 `input` 事件不触发展开，按钮 DOM 根本不存在（此前实探只验证了选择器匹配，未验证展开触发路径）。现正文改用 `execCommand("insertText")` 浏览器原生输入路径填写，并补发 keydown/keyup/click 事件兜底；按钮等待窗口放宽到 30s，期间用户手动点一下发博框即可自愈继续。
- **2026-10-21** v0.1.5 加固建发布页失败「Tabs cannot be edited right now (user may be dragging a tab)」（实测错误日志撞上）：标签拖拽中 Chrome 临时拒绝 tabs API，导致整轮分发创建失败。现 `tabs.create/update/group` 与 `tabGroups.update` 均带自动重试（500ms × 6 次，拖拽结束即恢复），重试耗尽才报错。
- **2026-10-21** v0.1.4 修豆瓣自动发布报「未找到发布按钮」：豆瓣发布按钮实为 `a.bn-flat` 包 `input[type=button]`（文字在 value 属性、textContent 为空），旧逻辑只扫 `button/a.btn` 的文本永远落空（已在登录态豆瓣页实探 DOM 确认）。现从编辑器邻近容器逐层向外找按钮，`value`/`textContent` 双通道匹配并排除外链，补 disabled 等待；编辑器选择器补 `textarea[placeholder*="分享"]` 显式命中（placeholder 为「此刻你想要分享...」，此前靠裸 textarea 兜底碰运气）。
- **2026-10-20** v0.1.3 豆瓣分发同样修末尾多出「收起」：与微博同机制（长文折叠控件混进编辑器内容流），给豆瓣 adapter 加同样的发布前后清洗逻辑。
- **2026-10-20** v0.1.2 修微博分发末尾多出「收起」二字：微博发博框在长文时会往编辑器内部塞「收起/展开」折叠控件，程序化粘贴后被一起发出去。现于填写正文后与点击发布前各清洗一次（删掉编辑器内文本恰为「收起/展开」的末尾控件及裸文本尾巴），手动/自动发布模式均生效。
- **2026-09-23** v0.1.1 修「分发后回来找不到按钮」：分发时即刻页在后台，setInterval 被 Chrome 节流到分钟级，React 重渲染丢按钮后补不回来。现改为 visibilitychange/focus + MutationObserver 即时补注入，另加工具栏图标兜底（点击强制恢复）；按钮换琥珀黄纸飞机图标。
- **2026-09-22** v0.1.0 首版：即刻帖子弹窗一键分发到 X / 微博 / 豆瓣，原画质图片、话题标签、附原帖链接、标签分组、自动点击发布可选项。
